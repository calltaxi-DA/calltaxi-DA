# ADR 0001: 모노레포 구성 및 기술 스택

- 상태: 결정됨 (2026-09-10)

## 배경

`calltaxi-DA`는 원래 순수 데이터분석 레포였다(README, 브랜치 전략, 의존성 전부 분석 파이프라인 전용). 별도로 기획된 장애인콜택시 추천 웹서비스(MVP)를 어느 레포에 둘지, 어떤 기술 스택으로 시작할지 결정이 필요했다.

## 결정

1. **별도 레포가 아니라 이 레포 안에 모노레포로 추가한다.** 분석 결과(대기시간 통계 등)를 서비스가 바로 참조하기 쉽고, 별도 레포 관리 오버헤드가 2일 MVP 일정에 맞지 않는다.
2. **백엔드: Python + FastAPI.** 팀이 이미 Python/pandas에 익숙하고, 분석 로직(대기시간 lookup 등)을 API에 그대로 재사용하기 쉽다.
3. **프론트엔드: Vite + React + TypeScript.** 지도 SDK 연동 사례가 많고 빠른 스캐폴딩이 가능하다.
4. **AI(대기시간/추천 로직)는 `ai/`로 별도 최상위 폴더로 분리하되, `backend/`와 가상환경은 공유한다.** 책임(HTTP 계층 vs 순수 로직)은 나누되, 둘 다 Python이고 같은 프로세스에서 실행되므로 별도 가상환경을 두는 것은 과도한 분리로 판단했다.
5. **기존 `src/`(data_ingestion, preprocessing)는 그대로 두고 건드리지 않는다.** 오프라인 배치용 코드와 서비스가 실시간으로 쓰는 `ai/` 코드는 목적이 다르다.

## 대안 및 기각 사유

- **별도 서비스 레포**: 데이터 동기화가 번거롭고, 2일짜리 MVP에 레포 2개를 유지할 여력이 없다고 판단해 기각.
- **Java + Spring Boot**: 팀 대다수가 Python에 더 익숙하고, 분석 코드 재사용 이점이 없어 기각.
- **backend와 ai를 하나의 폴더로 합치기**: 사용자가 책임 구분을 명시적으로 요구했고, HTTP 계층과 순수 로직을 분리해두면 이후 `ai/`만 별도 배포(예: 배치 재계산 잡)하기도 쉬워 유지.
