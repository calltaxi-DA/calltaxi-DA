# ADR 0005: Backend 소유 교통비 기록과 SQLite 저장

- 상태: 승인
- 날짜: 2026-09-13

## 배경

선택한 이동경로의 실제 이용금액을 날짜별로 기록하고, 같은 조건의 금액 우선 추천 비용과 월별로 비교해야 한다. 기존 서비스에는 사용자 생성 데이터 저장소가 없었고 Frontend가 추천 비용이나 절약액을 계산하면 ADR 0004의 Backend 소유 추천 계약과 충돌한다.

병원 이동 분석은 검토 완료 export로만 보존하고 현재 서비스에서 제공하지 않으므로 이번 기능과 연결하지 않는다.

## 결정

- `backend/`가 교통비 기록과 집계를 소유하고 Python 표준 라이브러리 `sqlite3`로 영속화한다.
- 기본 파일은 저장소 기준 `backend/var/transport_costs.sqlite3`이며 `APP_TRANSPORT_COST_DB_PATH`로 변경할 수 있다. 런타임 DB는 Git에 커밋하지 않는다.
- 생성 요청은 이용 날짜, 실제 이용금액, 선택한 이동수단과 기존 추천의 출발지·목적지·후보 이동수단만 받는다.
- Backend는 저장 시점에 후보 경로를 다시 생성하고 `cost → time → walk` 순서로 정렬한 1위의 비용과 이동수단을 저장한다. 클라이언트가 추천 비용을 제출할 수 없다.
- 절약 가능 금액은 기록별 `max(실제 이용금액 - 금액 우선 추천 비용, 0)`으로 정의하고 Backend가 계산한다.
- 일별 API는 원본 기록과 합계를, 월별 API는 날짜별 집계와 월 합계를 반환한다.
- 현재 단계는 인증 없는 단일 사용자·단일 Backend 인스턴스 범위다. 생성과 조회만 제공하며 수정·삭제·결제 연동은 제외한다.

## 결과

- SQLite는 별도 서버 없이 현재 로컬 서비스 범위에서 영속성을 제공하고 테스트마다 임시 DB로 격리할 수 있다.
- 다중 사용자 분리와 여러 Backend 인스턴스의 동시 운영은 지원하지 않는다. 해당 요구가 확정되면 사용자 소유권과 migration 전략을 먼저 설계한 뒤 서버형 DB를 검토한다.
- 외부 경로 API 또는 비용 지표를 사용할 수 없으면 추천 비용을 임의 값으로 저장하지 않고 생성 요청을 `503`으로 실패시킨다.
