# 버스 공식 API 실제 검증 기준

상태: 완료 / 현재 조건 기준 최종 판정 (2026-09-12)
목적: Analysis Phase 6-2에서 버스 추가 데이터 후보의 호출 가능성과 수집 방법을 검증하고 현재 서비스 적용 범위를 확정한다.

## 이번 문서의 성격

이 문서는 Phase 6-2의 검증 결과와 현재 조건에서의 최종 판정을 기록한 완료 산출물이다.

현재 루트 `.env`에는 서울 버스 위치·도착 API용 공식 인증키가 설정되어 있다. 그러나 공식 endpoint가 `http://ws.bus.go.kr` 평문 HTTP만 제공하므로 키를 전송하지 않는다. 용도가 확정되지 않은 `MOBILITY_API_KEY` 역시 전송하지 않는다.

실제 성공 응답이 없는 항목은 성공한 것으로 간주하지 않고, 보안·인증·데이터 제공 형태를 근거로 `가능`, `조건부`, `불가`를 판정한다.

## 작업 전제

실제 호출 검증을 재개하려면 필요한 것:

1. 서울 버스 위치/도착 API의 공식 HTTPS endpoint 또는 HTTPS gateway
2. ODsay 서버 API 호출이 가능한 인증키와 권한/IP 설정
3. 샘플 노선 ID, 정류장 ID, ARS ID
4. ODsay 버스 경로 응답의 정류장/노선 ID 형식

## 2026-09-12 실제 확인 결과

- 루트 `.env`에 서울 버스 위치/도착 API용 공식 인증키를 설정했고, 사용자가 공공데이터포털에서 두 서비스의 승인 상태를 확인했다. 키 값은 기록하지 않았으며 용도가 확정되지 않은 `MOBILITY_API_KEY`도 전송하지 않았다.
- 서울 버스위치정보조회 서비스의 [공공데이터포털 공식 카탈로그](https://www.data.go.kr/data/15000332/openapi.do)에서 노선 ID·정류소 구간을 입력으로 받고, 차량 위치·차량번호·차량유형·혼잡도 등을 제공하는 서비스임을 확인했다. 이는 문서 확인 결과이며 실제 응답 필드명과 코드값 검증 결과는 아니다.
- 서울 버스도착정보조회 서비스의 [공공데이터포털 공식 카탈로그](https://www.data.go.kr/data/15000314/openapi.do)에서 첫 번째·두 번째 도착 버스의 예측 도착시간, 차량번호, 버스유형, 혼잡도, 만차·막차 여부와 배차간격을 제공 대상으로 설명함을 확인했다. 실제 응답 필드명·값·갱신주기는 아직 검증하지 않았다.
- 서울 열린데이터광장의 [특정차량 위치정보 안내](https://data.seoul.go.kr/dataList/OA-15340/L/1/datasetView.do)는 요청 URL을 `http://ws.bus.go.kr/api/rest/buspos`로 안내한다. 공식 HTTPS 대체 endpoint가 확인되기 전에는 인증키를 전송하지 않는다.
- 공공데이터포털 승인 화면과 상세기능을 사용자와 재확인했으나 별도 HTTPS endpoint는 제공되지 않았다. 키 없이 HTTP 위치 endpoint에 요청했을 때 서버는 `401`과 `serviceKey 파라미터가 필요합니다.`를 반환해 HTTP 서비스 자체는 도달 가능함을 확인했다. HTTPS endpoint는 연결 timeout이 발생했다. 따라서 위치·도착 API는 공식 HTTPS gateway가 제공되기 전까지 이 프로젝트에서 직접 호출하지 않는다.
- `.env`의 기존 `ODSAY_API_KEY`로 `https://api.odsay.com/v1/api/searchPubTransPathT`에 버스 전용 경로를 실제 요청했다. HTTP 상태는 `200`이었지만 응답은 오류 코드 `500`, 메시지 `[ApiKeyAuthFailed] ApiKey authentication failed.`였고 경로 데이터는 없었다. 키 값과 요청 URL의 query string은 기록하지 않았다.
- T-DATA의 `TPSS_재차인원_노선_구간`은 일자별·시간대별·노선별·구간별 승객수 **파일 데이터**로 확인했다. 별도의 [버스 운행 정보 Open API](https://t-data.seoul.go.kr/category/dataviewopenapi.do?data_id=1084)는 재차인원 필드 후보를 문서화하지만, 실제 호출·데이터 시점·차량 단위 활용 가능성은 미검증이다. [T-DATA Open API 이용안내](https://t-data.seoul.go.kr/userguide/guideopenapi.do)에 따르면 개발자 활용신청은 별도 인증키가 필요하고 일 최대 1,000건을 요청할 수 있다.

## 실제 호출 시 샘플

Phase 6-2 실제 검증에서는 최소 10~20개 노선을 확인한다. 1차 샘플은 기존 route master에 존재하고 운행 규모가 큰 노선부터 선택한다.

예시 후보:

| 노선번호 | 내부 후보 노선 ID | 선택 이유 |
|---|---|---|
| 100 | 100100549 | 간선, 저상버스 정보 있음 |
| 101 | 100100006 | 간선, 저상버스 정보 있음 |
| 146 | 100100025 | 간선, 저상버스 정보 있음 |
| 271 | 100100038 | 간선, 저상버스 정보 있음 |
| 401 | 100100073 | 간선, 저상버스 정보 있음 |
| 0017 | 미확인 | processed 승하차에는 있으나 route master 범위와 차이 확인 필요 |

주의: `analysis/bus/low_floor_bus_route_master.csv`의 `seoul_route_id`가 서울 버스 API의 `busRouteId`와 동일한지는 아직 검증하지 않았다.

## 검증 절차

1. 서울 버스 API의 공식 HTTPS endpoint 또는 HTTPS gateway를 확인한다.
2. 위치정보 API에서 샘플 노선의 운행 차량 목록을 조회한다.
3. 응답에서 차량 ID, 차량번호, 차량유형, 혼잡도 필드가 실제로 존재하는지 확인한다.
4. 차량유형 코드가 저상버스 여부를 의미하는지 공식 코드표 또는 샘플 대조로 확인한다.
5. 도착정보 API에서 샘플 정류장·노선의 도착예정정보를 조회한다.
6. 정류장 ID, ARS ID, ODsay 정류장 ID가 연결 가능한지 확인한다.
7. 배차간격 필드가 직접 제공되는지 확인한다.
8. 직접 제공되지 않으면 동일 노선 연속 차량의 도착예정시각 또는 위치 timestamp 기반 headway 계산 가능성을 검증한다.
9. 각 항목을 `가능`, `조건부`, `불가`로 판정한다.

| 차량별 저상버스 여부 | 불가 | “곧 도착하는 저상버스” 판단에 사용하지 않음 | HTTPS 응답과 차량유형 코드 정의 확보 시 재검토 |
| 실시간 혼잡도 | 불가 | “현재 혼잡” 판단에 사용하지 않음 | HTTPS 응답과 혼잡도 코드 정의 확보 시 재검토 |
| 실시간 배차간격·headway | 불가 | 대기시간 또는 추천 정렬에 사용하지 않음 | HTTPS 도착·위치 응답 확보 시 재검토 |
| T-DATA 재차인원 | 조건부 | 파일/운행 이력을 오프라인 분석하고 사람이 `analysis/`로 export한 집계만 후보 | 활용승인, 실제 값·시점·ID 검증 필요 |
| ODsay ↔ 서울 BIS/ARS ID mapping | 조건부 | 현재 서비스 연결에 사용하지 않음 | ODsay 서버 인증 정상화 후 실제 응답 매핑률 검증 필요 |

## 재검토 blocker

| blocker | 영향 | 필요한 조치 |
|---|---|---|
| 서울 버스 API의 HTTPS endpoint 미제공 | 공식 키는 준비됐지만 HTTP query로만 전송할 수 있어 직접 호출 중단 | 공식 HTTPS gateway가 제공될 때 재검토하고, 그전에는 현재 정적·집계 데이터 범위 유지 |
| ODsay 버스 응답 인증 실패 | 실제 호출에서 `[ApiKeyAuthFailed]`가 재현되어 ODsay ↔ 서울 BIS/ARS ID mapping 불가 | ODsay 키 종류·권한·등록 도메인/IP 확인 후 재호출 |
| 차량유형 코드 의미 미확인 | 저상버스 여부 단정 불가 | 공식 코드표 또는 샘플 대조 필요 |
| 배차간격 수집 방식 미확정 | 대기시간/추천 조건에 반영 불가 | 공식 필드 확인 또는 headway 계산 검증 |

## 서비스 적용 결론

Phase 6-2는 현재 이용 가능한 인증·전송 조건에서 각 후보의 `가능`, `조건부`, `불가` 판정을 완료했다. `조건부`와 `불가` 항목의 재검토 조건이 충족되기 전까지 서비스 적용 범위는 아래 수준으로 제한한다.

- 노선 단위 저상버스 접근성
- 2025년 집계 기반 혼잡 위험 보조지표

실시간 저상버스 도착, 차량별 저상버스 여부, 실시간 혼잡도, 배차간격은 현재 서비스 기능에서 제외한다. 공식 HTTPS 응답과 코드 정의를 확보한 뒤 별도 후속 Phase에서 재검토한다.
