# 버스 공식 API 실제 검증 기준

상태: 미완료 / 키 준비 대기 (2026-09-12)  
목적: Analysis Phase 6-2에서 버스 추가 데이터 후보를 실제 공식 API 응답으로 검증하기 위한 기준과 현재 blocker를 정리한다.

## 이번 문서의 성격

이 문서는 Phase 6-2의 완료 산출물이 아니라, 실제 API 호출을 진행하기 위한 검증 계획과 현재 blocker 기록이다.

현재 루트 `.env`에는 서울 버스 API용 공식 인증키로 확인된 값이 없다. `MOBILITY_API_KEY`는 존재하지만, 해당 키의 용도와 호출 대상이 서울 버스 위치/도착 API라고 확정되지 않았고, 일부 서울 버스 API 후보 endpoint가 `http://ws.bus.go.kr` 평문 HTTP를 사용하므로 임의 전송하지 않는다.

따라서 이번 단계에서는 실제 API 호출 성공 여부, 응답 필드 의미, 서비스 적용 가능성을 확정하지 않는다.

## 작업 전제

실제 호출 검증 전 필요한 것:

1. 서울 버스 위치/도착 API에 사용할 공식 인증키
2. 해당 키의 사용 가능 서비스 범위
3. HTTP endpoint만 제공되는 경우 키 전송 방식과 보안 허용 여부
4. 샘플 노선 ID, 정류장 ID, ARS ID
5. ODsay 버스 경로 응답의 정류장/노선 ID 형식

## 실제 호출 시 샘플

Phase 6-2 실제 검증에서는 최소 10~20개 노선을 확인한다. 1차 샘플은 기존 route master에 존재하고 운행 규모가 큰 노선부터 선택한다.

예시 후보:

| 노선번호 | 내부 후보 노선 ID | 선택 이유 |
|---|---|---|
| 100 | 100100549 | 간선, 저상버스 정보 있음 |
| 101 | 100100006 | 간선, 저상버스 정보 있음 |
| 146 | 100100025 | 간선, 저상버스 정보 있음 |
| 271 | 100100038 | 간선, 저상버스 정보 있음 |
| 401 | 100100073 | 간선, 저상버스 정보 있음 |
| 0017 | 미확인 | processed 승하차에는 있으나 route master 범위와 차이 확인 필요 |

주의: `analysis/bus/low_floor_bus_route_master.csv`의 `seoul_route_id`가 서울 버스 API의 `busRouteId`와 동일한지는 아직 검증하지 않았다.

## 검증 절차

1. 서울 버스 API용 공식 인증키로 확인된 값을 `.env`에 추가한다. 실제 backend 구현 전까지 환경변수명은 확정하지 않는다.
2. 위치정보 API에서 샘플 노선의 운행 차량 목록을 조회한다.
3. 응답에서 차량 ID, 차량번호, 차량유형, 혼잡도 필드가 실제로 존재하는지 확인한다.
4. 차량유형 코드가 저상버스 여부를 의미하는지 공식 코드표 또는 샘플 대조로 확인한다.
5. 도착정보 API에서 샘플 정류장·노선의 도착예정정보를 조회한다.
6. 정류장 ID, ARS ID, ODsay 정류장 ID가 연결 가능한지 확인한다.
7. 배차간격 필드가 직접 제공되는지 확인한다.
8. 직접 제공되지 않으면 동일 노선 연속 차량의 도착예정시각 또는 위치 timestamp 기반 headway 계산 가능성을 검증한다.
9. 각 항목을 `가능`, `조건부`, `불가`로 판정한다.

## 현재 blocker

| blocker | 영향 | 필요한 조치 |
|---|---|---|
| 서울 버스 API용 공식 인증키 미확인 | 실제 호출 불가 | 사용할 공식 인증키와 적용 API 범위 확인 |
| HTTP endpoint 키 전송 보안 확인 필요 | 평문 전송 위험 | HTTPS 대체 endpoint 존재 여부 확인 또는 사용 허용 범위 확인 |
| ODsay 버스 응답 인증 실패 | ODsay ↔ 서울 BIS/ARS ID mapping 불가 | ODsay 키/권한/IP 문제 해결 |
| 차량유형 코드 의미 미확인 | 저상버스 여부 단정 불가 | 공식 코드표 또는 샘플 대조 필요 |
| 배차간격 수집 방식 미확정 | 대기시간/추천 조건에 반영 불가 | 공식 필드 확인 또는 headway 계산 검증 |

## 최종 판단

현재 상태에서는 Phase 6-2를 완료 처리할 수 없다.

키와 실제 응답이 준비되기 전까지 서비스 적용 가능 범위는 Phase 6-1에서 확정한 아래 수준으로 유지한다.

- 노선 단위 저상버스 접근성
- 2025년 집계 기반 혼잡 위험 보조지표

실시간 저상버스 도착, 차량별 저상버스 여부, 실시간 혼잡도, 배차간격은 실제 API 호출 검증 이후에만 서비스 기능으로 확정한다.
