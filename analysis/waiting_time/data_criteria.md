## 공통 입력 데이터 기준

통합 대기시간 Prediction 모델의 1차 기준 입력은 공통 정제 탑승내역이다.

```text
data/processed/서울시설공단_장애인콜택시 탑승내역_정제_20251231.csv
```

필수 컬럼은 다음과 같다.

| 구분 | 컬럼 |
|---|---|
| 시간 | `접수일시`, `예정일시`, `배차일시`, `승차일시`, `하차일시`, `취소일시` |
| 위치 | `출발구`, `출발동`, `목적구`, `목적동` |
| 이용 정보 | `차량구분`, `이용목적`, `승차거리`, `요금`, `장애유형` |

시간 컬럼은 `pd.to_datetime(..., errors="coerce")` 기준으로 변환한다. 변환 실패 또는 실제 결측은 결측으로 유지하고, 임의 보간하지 않는다.

## 공통 대기시간 파생 변수

대기시간은 모두 분 단위로 계산한다.

| 컬럼 | 계산식 | 용도 |
|---|---|---|
| `접수_배차_분` | `배차일시 - 접수일시` | 핵심 예측/분석 지표. 차량 배정까지의 대기시간 |
| `접수_승차_분` | `승차일시 - 접수일시` | 이용자 체감 승차 대기시간 |
| `접수_취소_분` | `취소일시 - 접수일시` | 취소까지의 대기시간 |
| `배차_취소_분` | `취소일시 - 배차일시` | 배차 후 취소 패턴 |
| `배차_승차_분` | `승차일시 - 배차일시` | 배차 후 차량 접근·승차까지의 보조 지표 |

서비스의 통합 대기시간 Prediction 모델에서 우선 사용할 목표값은 `접수_배차_분`이다. 이유는 경로 추천 서비스에서 사용자가 체감하는 “대기 시작 후 차량 배정까지의 불확실성”을 먼저 줄이는 것이 목적이고, Notebook 분석에서도 장시간 대기 병목이 `접수→배차`에서 크게 나타났기 때문이다.

`접수_승차_분`은 보조 목표 또는 검증 지표로 유지한다. `배차_승차_분`은 차량 배정 이후 접근 시간 성격이 강하므로 Prediction 모델의 1차 목표값으로 사용하지 않는다.

## 결측치 처리 기준

- 시간 컬럼 결측은 실제 미발생 또는 기록 누락으로 보고 유지한다.
- 목표값 계산에 필요한 두 시간 중 하나라도 결측이면 해당 목표값은 결측으로 둔다.
- 승차완료 모델 학습에는 `접수일시`, `배차일시`, `승차일시`가 있는 건을 우선 사용한다.
- 취소 분석은 별도 보조 분석으로 유지하고, 승차완료 대기시간 모델의 목표값 학습에 섞지 않는다.
- 결측을 평균/중앙값으로 대체하지 않는다. 대기시간은 운영 이벤트 순서의 결과라 임의 대체 시 실제 대기 패턴을 왜곡할 수 있다.

## 이상치 처리 기준

- 대기시간 파생 컬럼이 음수인 경우 시간 순서 이상으로 본다.
- 음수 대기시간은 정상 대기시간으로 해석하지 않고 결측 처리하거나 모델 학습 대상에서 제외한다.
- 시간 순서 정상성은 최소한 아래 기준으로 확인한다.

```text
접수일시 <= 배차일시 <= 승차일시 <= 하차일시
```

- 취소 건은 `승차일시`가 없을 수 있으므로 승차완료 건과 동일한 정상성 기준을 그대로 적용하지 않는다. 취소 건은 `접수_취소_분`, `배차_취소_분` 중심으로 별도 확인한다.

## 차량구분 기준

`차량구분`은 통합 모델의 핵심 입력 변수로 유지한다.

| 차량구분 | 기준 |
|---|---|
| `임차택시` | 바로콜 중심 데이터로 사용한다. 예약 목적 또는 장시간 예외는 본 분석에서 제외한다. |
| `특장차` | 바로콜, 전일접수, 심야시간 사전예약 후보를 구분한다. 단일 기준으로 임의 통합하지 않는다. |

통합 Prediction 모델은 특장차/임차택시를 별도 모델로 나누지 않고 하나의 모델로 가져가되, `차량구분`과 접수유형 후보를 feature로 포함하는 방향을 기준으로 한다.

## 임차택시 기준

출처: `notebooks_waiting_time/01_rental_wait_time_data_preprocessing.ipynb`

임차택시는 운영상 바로콜만 가능한 것으로 확인되었으나, 원자료에는 `이용목적`에 예약이 포함된 건과 접수 후 승차까지 매우 긴 건이 존재한다. 이 건은 바로콜 대기시간을 왜곡할 수 있으므로 본 분석에서 제외하고 예외 확인 대상으로 보관한다.

| 항목 | 기준 |
|---|---|
| 대상 | `차량구분 == "임차택시"` |
| 공간 범위 | 출발구 또는 목적구 중 하나 이상이 서울 25개 자치구에 속하는 건. 서울 외→서울 외 이동은 제외 |
| 예약 목적 여부 | `이용목적` 문자열에 `예약` 포함 |
| 바로콜 포함 | 예약 목적이 아니고 `접수_승차_분`이 0~250분인 건 |
| 장시간 예외 | 예약 목적이 아니고 `접수_승차_분 > 250`인 건 |
| 제외 사유 | `예약 목적 포함`, `접수→승차 250분 초과`, `시간 순서 이상` |
| 취소 분석 | 승차일시가 없을 수 있으므로 `이용목적` 기준으로 `바로콜 취소`와 `예약성 예외 취소`를 구분 |

임차택시는 접수일자와 승차일자의 날짜 차이만으로 제외하지 않는다. 자정을 넘겼더라도 `접수_승차_분`이 정상 범위 안이면 바로콜 정상 건으로 포함한다.

## 특장차 기준

출처:

- `notebooks_waiting_time/03_wait_time_data_preprocessing.ipynb`
- `src/waiting_time/special_vehicle_preprocessing.py`
- `notebooks_waiting_time/04_special_vehicle_wait_time_analysis.ipynb`

특장차는 바로콜, 전일접수, 정기접수, 심야시간 사전예약이 모두 가능한 차량 유형이다. 따라서 전처리 1단계에서는 접수유형을 자동 확정하지 않고 `특장차_접수유형`을 비워 두며, `특장차_접수유형_분류상태`를 `미분류`로 생성한다.

전처리 공통 기준은 다음과 같다.

| 항목 | 기준 |
|---|---|
| 대상 | `차량구분 == "특장차"` |
| 공간 범위 | 출발구 또는 목적구 중 하나 이상이 서울 25개 자치구에 속하는 건. 서울 외→서울 외 이동은 제외 |
| 대기시간 | 공통 5개 대기시간 컬럼 생성 |
| 음수 시간 | 결측 처리 |
| 시간 변수 | `접수시간대`, `접수시간대_HH`, `접수요일`, `평일주말` 생성 |
| 이동유형 | `구 내 이동`, `구 간 이동`, `서울→서울 외`, `서울 외→서울` |
| 거리 변수 | `승차거리_km`, `승차거리구간` 생성 |

### 특장차 바로콜 후보

바로콜 후보는 전일접수 후보와 심야시간 사전예약 후보를 제외한 뒤 아래 기준으로 정의한다.

- 당일 접수·당일 승차
- 또는 자정을 넘겼더라도 `접수_승차_분`이 0~200분인 건
- 정기접수 가능패턴은 고객 ID가 없어 확정할 수 없으므로 제외 조건으로 쓰지 않고 참고 플래그로만 유지

바로콜 대기시간 분석의 핵심 목표값은 `접수_배차_분`이다. 장시간 대기 기준은 Notebook 분석에서 접수→배차 90분위수 약 72.1분으로 확인되었고, 실무 해석 편의를 위해 75분 이상을 장시간 대기 기준으로 사용할 수 있다.

### 특장차 전일접수 후보

전일접수 후보는 심야시간 사전예약 후보를 제외한 뒤 아래 기준으로 정의한다.

```text
접수일자 = 예정일자 - 1일
접수시간대가 07시, 08시, 10시 중 하나
예정시간대가 07시, 08시, 10시 중 하나
```

전일접수는 예약성 접수이므로 바로콜처럼 `접수일시` 기준의 `접수→배차`, `접수→승차`를 그대로 체감 대기시간으로 해석하지 않는다. 전일접수 분석과 모델 feature에서는 아래 예정시각 기준 파생 변수를 함께 사용한다.

| 컬럼 | 계산식 |
|---|---|
| `예정시각기준_배차_분` | `배차일시 - 예정일시` |
| `예정시각기준_승차_분` | `승차일시 - 예정일시` |
| `예정시각기준_취소_분` | `취소일시 - 예정일시` |

전일접수 시간대별 정원 기준은 후보 제외 조건이 아니라 검증 지표로만 사용한다.

### 특장차 심야시간 사전예약 후보

심야시간 사전예약 후보는 다음 기준으로 확인한다.

- 접수일자 = 예정일자 - 1일
- 접수시 10~18시
- 예정시 01~05시
- 서울 외 관련 이동은 예정시각 03:59:59 이하 기준을 별도 검증

심야시간 사전예약 역시 예약성 접수이므로 예정시각 기준 파생 변수를 함께 사용한다. 표본 수가 작을 수 있으므로 시간대별 수치를 과도하게 일반화하지 않는다.

### 정기접수

정기접수는 동일 이용자가 정기적으로 동일 시각, 동일 출발지, 동일 목적지로 이동하는 경우에 해당한다. 현재 데이터에는 고객 ID가 없으므로 반복 패턴만으로 정기접수를 확정하지 않는다.

따라서 정기접수는 접수유형으로 확정 분류하지 않고 `정기접수_가능패턴여부` 같은 보조 플래그로만 확인한다.

## 전일접수·당일접수 처리 기준

서비스의 1차 대기시간 Prediction에서는 **당일 즉시 이용 판단**과 **예약성 접수 판단**을 분리한다.

| 구분 | 처리 |
|---|---|
| 임차택시 당일 바로콜 | 모델의 기본 학습 대상 |
| 임차택시 예약 목적/250분 초과 | 모델 기본 학습 대상에서 제외, 예외 확인용 |
| 특장차 바로콜 후보 | 모델의 기본 학습 대상 |
| 특장차 전일접수 후보 | 바로콜 모델과 섞지 않고 예정시각 기준 feature/별도 세그먼트로 관리 |
| 특장차 심야시간 사전예약 후보 | 예정시각 기준 feature/별도 세그먼트로 관리 |
| 정기접수 가능패턴 | 확정 분류하지 않고 참고 플래그로만 유지 |

운영 서비스에서 사용자가 “지금 출발” 경로를 찾는 경우에는 바로콜 후보 기준의 대기시간이 우선이다. 전일접수·심야시간 사전예약은 예약성 접수이므로 당일 즉시 호출 대기시간 판단에 그대로 섞지 않는다.

## 통합 모델 기준

통합 장애인 콜택시 대기시간 Prediction 모델의 1차 기준은 다음과 같다.

- 모델은 하나로 통합한다.
- `차량구분`은 feature로 포함한다.
- 특장차 접수유형 후보(`바로콜`, `전일접수`, `심야시간 사전예약`, `미분류/기타`)는 feature 또는 세그먼트로 포함한다.
- 1차 목표값은 `접수_배차_분`이다.
- 보조 목표/검증 지표로 `접수_승차_분`을 유지한다.
- 취소 건은 승차완료 대기시간 모델 학습에 섞지 않고, 취소 위험/운영 병목 분석의 보조 데이터로 둔다.
- 전일접수와 심야시간 사전예약은 `예정일시` 기준 파생 변수를 함께 사용한다.

## 서비스 개발에서 확정적으로 사용할 기준

Backend/Frontend 서비스가 이후 대기시간 예측 결과를 사용할 때의 기준은 다음과 같다.

1. 서비스는 `data/`나 `notebooks*/`를 직접 읽지 않는다.
2. 모델 또는 lookup 결과가 안정화되면 사람이 검토해 `analysis/`에 export한다.
3. `ai/waiting_time/`은 `analysis/`의 export 산출물만 읽는다.
4. 모델 미연결 상태에서는 기존 규칙대로 `NotImplementedError`를 유지한다.
5. 프론트/백엔드는 예측 실패 또는 미연결 상태를 명시적으로 처리한다.
